# 権限とロール

権限は**システムレベル**と**サイトレベル**の2つに分かれ、**設定する場所が違う**。

| | 何を許すか | どう与えるか |
| --- | --- | --- |
| **システムレベル** | サイトの作成、ユーザー管理、管理画面へのサインインなど | ユーザーの `systemPermissions` に直接 |
| **サイトレベル** | 記事の作成、テンプレートの編集、コメント管理など | **ロールにまとめて**、サイト単位でユーザーかグループに |

**「システム管理者」権限を持つユーザーが最低1人必要。**

```bash
# サイトレベル（ロール経由）
mtb roles list --fields id,name
mtb sites permissions grant --site-id 4 --user-id 2 --role-id 2
mtb sites permissions list --site-id 4
mtb sites permissions revoke --site-id 4 --user-id 2 --role-id 2

# システムレベル（ユーザーに直接）
mtb users update 2 --user '{"systemPermissions":["sign_in_data_api","create_site"]}'
```

## Data API でユーザーを使えるようにする（3つの関門）

**API で作ったユーザーは、そのままでは Data API にサインインできない。** 3つ揃って初めて通る。

1. **`sign_in_data_api` システム権限**
   認証エンドポイントが明示的に確認する（`MT/DataAPI/Endpoint/v1/Auth.pm`）。
   `mtb users update <id> --user '{"systemPermissions":["sign_in_data_api"]}'` で付けられる。

2. **Webサービスパスワード**
   Data API のサインインに使うパスワード。**サインイン用パスワードとは別物**。
   **Data API からは設定も取得もできない。** MT が自動生成するもので、値を選ぶこともできない。
   管理画面（ユーザー編集 → Webサービスパスワード）で [新しいパスワードを発行] を押し、
   表示された値をコピーして渡す。ユーザー作成時に初期パスワードが設定されている。

3. **サイト側で Data API が許可されていること**
   サイト設定 → Web サービス の [Data API のアクセスを許可する]。
   ここが切れていると、そのサイトには API で触れない。

**ユーザーを作ったら、この3点を相手に伝えること。** 1 は API でできるが、2 と 3 は管理画面の作業。

## 組み込みロール

**まずこれで足りないか確かめる。** 9種類ある。

| ID | ロール | 権限 | できること |
| --- | --- | --- | --- |
<!-- roles:begin -->
| 1 | Site Administrator | `administer_site` | サイトの管理者。サイトのすべてを扱える |
| 2 | Editor | 14 | すべての記事・ページ・カテゴリ・フォルダ・タグを編集し、アップロードと公開ができる |
| 3 | Author | 5 | 記事を作り、自分の記事を編集し、アップロードと公開ができる |
| 4 | Designer | 5 | テンプレートとテーマを編集・管理・公開できる |
| 5 | Webmaster | 3 | ウェブページの管理、アップロード、サイトと子サイトのテンプレートの公開ができる |
| 6 | Contributor | 2 | 記事を作り、自分の記事を編集し、コメントできる（公開はできない） |
| 7 | Content Designer | 3 | コンテンツタイプ・コンテンツデータ・カテゴリセットを管理できる |
| 8 | Moderator | 2 | コメントし、コメントとトラックバックを管理できる |
| 9 | Commenter | `comment` | コメントできる |
<!-- roles:end -->

## システムレベルの権限（12）

| キー | 名前 | 内容 |
| --- | --- | --- |
| `administer` | システム管理者 | システム全体の管理。すべての設定と機能 |
| `edit_templates` | テンプレートの管理 | グローバルテンプレートを含む全サイトのテンプレート。**カスタムフィールドの管理にも必要** |
| `manage_plugins` | プラグインの管理 | プラグインの有効・無効と設定 |
| `view_log` | システムログの閲覧 | システム全体のログ |
| `sign_in_cms` | 管理画面へのサインイン | 管理画面に入れる |
| `sign_in_data_api` | Data API でのサインイン | **これが無いと Data API の認証が通らない** |
| `create_site` | サイトの作成 | 親サイトを作れる。**作った人にはそのサイトのウェブサイト管理者ロールが自動で付く** |
| `create_website` | ウェブサイトの作成 | |
| `create_blog` | 子サイトの作成 | |
| `manage_users_groups` | ユーザーとグループの管理 | ユーザーの新規登録、グループとメンバーの管理 |
| `manage_content_data` | コンテンツデータの管理 | 全サイトのコンテンツデータ |
| `manage_content_types` | コンテンツタイプの管理 | 全サイトのコンテンツタイプ |

## サイトレベルの権限（31）

### 管理

| キー | 名前 | 内容 |
| --- | --- | --- |
| `administer_site` | サイトの管理 | そのサイトのすべてのサイトレベル権限 |
| `administer_website` / `administer_blog` | ウェブサイト／ブログの管理 | 種別ごとの管理者 |
| `manage_member_blogs` | 子サイトを含む管理 | |
| `create_site` | サイトの作成 | 子サイトを作れる |
| `edit_config` | 設定の変更 | サイト設定の保存。記事のインポート・エクスポートも |
| `edit_categories` | カテゴリの管理 | 作成と並び替え |
| `manage_category_set` | カテゴリセットの管理 | |
| `edit_tags` | タグの管理 | 名前の変更、削除 |
| `edit_notifications` | アドレス帳の管理 | **標準では無効**（`mt-config.cgi` の `EnableAddressBook` を 1 に） |
| `manage_users` | ユーザーの管理 | サイトレベル権限の付与・削除。**ユーザーの新規作成や削除はできない** |
| `set_publish_paths` | 公開パスの設定 | 「設定の変更」を持つ人に、全般設定の公開パスも許す |
| `view_blog_log` | ログの閲覧 | サイトのログ |

### 作成と公開

| キー | 名前 | 内容 |
| --- | --- | --- |
| `create_post` | 記事の作成 | 新規作成と、**自分が作った記事**の編集・削除。自分の記事へのコメント管理も |
| `publish_post` | 記事の公開 | 「記事の作成」を持つ人に付けて、自分の記事を公開できるようにする |
| `send_notifications` | 通知の送信 | 同上。自分の記事について通知を送れる |
| `edit_all_posts` | すべての記事の編集 | 全記事の編集・公開とコメント管理。**この権限だけでは新規作成できない**（`create_post` が別に要る） |
| `manage_pages` | ウェブページの管理 | ページとフォルダの作成・編集・管理 |
| `rebuild` | サイトを再構築 | |
| `manage_content_data` | コンテンツデータの管理 | サイト内すべてのコンテンツデータの作成・編集・削除 |

| `manage_themes` | テーマの管理 | 切り替えとエクスポート |

| キー | 名前 | 内容 |
| --- | --- | --- |
| `upload` | ファイルアップロード | |
| `edit_assets` | アセットの管理 | サイトのすべてのアセット |

### コメント

| キー | 名前 | 内容 |
| --- | --- | --- |
| `comment` | コメントの投稿 | **これだけの人は、`sign_in_cms` があっても管理画面にサインインできない** |
| `manage_feedback` | コメントの管理 | サイトのすべてのコメント |

**MT 9 クラウド版ではコメントは標準で無効。** 使うには Comments プラグインを有効にする。

## コンテンツタイプごとの権限

`manage_content_data` はサイト内の全コンテンツタイプに効くが、**特定のタイプだけに絞れる**。
さらに**コンテンツフィールド単位で編集権限を付けられる**ので、作成者に触らせたくない項目を守れる。

キーは `manage_content_data:<コンテンツタイプのUUID>` の形で、タイプごとに違う。
タイプ単位では次が使える。

- コンテンツデータの管理（そのタイプの全データの作成と管理）
- コンテンツデータの作成
- コンテンツデータの公開
- すべてのコンテンツデータの編集

ロールを組む前に `mtb sites content-types list <site> --fields id,name` で対象を確認する。
